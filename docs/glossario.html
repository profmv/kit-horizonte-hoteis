01

Origem e preparação dos dados

PMSSistema hoteleiro

Property Management System: sistema que controla reservas, check-in, check-out, quartos, hóspedes e parte da operação de um hotel.

No projeto
Explica por que reservas, hóspedes e quartos possuem identificadores próprios.
Problema simulado
Cadastros e datas podem chegar com padrões diferentes após integrações.
OTACanal de venda

Online Travel Agency: plataforma que vende hospedagens pela internet, como os canais fictícios BookNow e ViajaMais.

No projeto
A OTA traz reservas, mas cobra comissão.
Análise
Compare volume, receita bruta e receita líquida por canal.
Power QueryPreparação de dados

Editor de importação e transformação do Power BI. Cada ação vira uma etapa reproduzível da consulta.

No projeto
Serve para padronizar textos e datas, remover duplicatas e criar colunas auxiliares.
Boa prática
Nomeie etapas pela regra aplicada e preserve os dados brutos na origem.
ETLProcesso de dados

Extract, Transform, Load: extrair dados da origem, transformá-los e carregá-los no destino analítico.

No projeto
Extrair os CSVs, limpar no Power Query e carregar no modelo do Power BI.
Objetivo
Fazer o mesmo tratamento ser repetido a cada atualização.
Modelo normalizadoOrganização da origem

Estrutura que separa assuntos em tabelas para evitar repetição e inconsistências. Um hóspede, por exemplo, é cadastrado uma vez e referenciado nas reservas.

No projeto
A V2 traz sete tabelas separadas.
Próximo passo
Organize-as para análise, respeitando chaves, grãos e relações.
02

Modelagem

GrãoNível de detalhe

Define o que uma linha representa. Antes de calcular qualquer coisa, você precisa saber se a linha é uma reserva, uma noite, um consumo ou um chamado.

No projeto
reservas tem uma linha por estadia; consumos_extras, uma por lançamento.
Risco
Juntar grãos diferentes pode duplicar receita.
PK · Chave primáriaIdentificação

PK vem de Primary Key: coluna — ou conjunto de colunas — que identifica cada linha de uma tabela sem duplicação.

No projeto
Reserva_ID identifica uma reserva; Hotel_ID identifica um hotel.
Validação
No lado “1” de uma relação, a PK deve ser única e não vazia.
FK · Chave estrangeiraLigação

FK vem de Foreign Key: coluna que guarda o identificador de uma linha existente em outra tabela.

No projeto
reservas[Hospede_ID] aponta para hospedes[Hospede_ID].
Validação
Uma FK sem correspondência cria linha órfã e pode aparecer como “(Em branco)” no relatório.
CardinalidadeRegra da relação

Indica quantas linhas de uma tabela podem se relacionar com linhas da outra: um-para-um, um-para-muitos ou muitos-para-muitos.

No projeto
Um hotel possui muitos quartos; um quarto pertence a um hotel.
Alerta
Muitos-para-muitos costuma indicar chave duplicada ou modelagem ainda não resolvida.
Relacionamento 1:NUm-para-muitos

Uma linha do lado “1” pode estar associada a várias linhas do lado “N”. O lado “1” precisa ter valores únicos.

No projeto
hoteis 1 → N quartos e reservas 1 → N consumos_extras.
Filtro
Prefira a direção do lado descritivo para o lado dos eventos.
DimensãoTabela descritiva

Tabela com atributos usados para filtrar, agrupar ou detalhar os resultados.

No projeto
Hotéis, Quartos, Hóspedes e Funcionários funcionam como dimensões.
Exemplo
Receita por cidade usa uma dimensão para explicar uma medida da tabela fato.
FatoTabela de eventos

Tabela que registra eventos mensuráveis e geralmente contém datas, chaves estrangeiras e valores numéricos.

No projeto
Reservas, Consumos Extras e Chamados são fatos com grãos diferentes.
Boa prática
Não una fatos apenas para reduzir o número de tabelas.
Esquema estrelaModelo analítico

Organização em que dimensões ficam ao redor de tabelas fato, criando caminhos de filtro simples e previsíveis.

No projeto
Dimensões descrevem as reservas, consumos e chamados sem repetir atributos em cada evento.
Benefício
Medidas mais claras, melhor desempenho e menos ambiguidade.
Ambiguidade no modeloRisco de relacionamento

Ocorre quando o filtro pode percorrer mais de um caminho entre as mesmas tabelas. O Power BI pode bloquear a relação ou produzir um resultado difícil de prever.

No projeto
Evite criar atalhos entre fatos quando as dimensões já oferecem o caminho correto.
Sinal de alerta
Relações bidirecionais adicionadas apenas para “fazer o número funcionar”.
03

Cálculos no Power BI

DAXLinguagem de fórmulas

Data Analysis Expressions: linguagem usada no Power BI para medidas, colunas calculadas e tabelas calculadas.

No projeto
Cria Receita, ADR, RevPAR, Ocupação, SLA e comparações de período.
Princípio
Uma fórmula DAX deve declarar claramente numerador, denominador e filtros.
MedidaCálculo dinâmico

Cálculo DAX avaliado no momento em que o visual é consultado. Seu resultado muda conforme filtros, linhas, colunas e segmentações.

No projeto
Receita Hospedagem muda ao selecionar hotel, período ou canal.
Diferença
Uma coluna calculada guarda valor por linha; uma medida calcula para o contexto atual.
Contexto de filtroSeleção ativa

Conjunto de condições que determina quais linhas participam de um cálculo. Pode vir de um visual, segmentação, página ou função DAX.

No projeto
Ao selecionar “Gramado”, as medidas devem considerar apenas as reservas ligadas ao hotel.
Teste
Coloque a medida em uma matriz e observe se total e linhas respondem corretamente.
KPIIndicador-chave

Key Performance Indicator: métrica escolhida para acompanhar um objetivo do negócio.

No projeto
ADR, RevPAR, Ocupação e SLA são KPIs.
Para decidir
Mostre valor, comparação e direção desejada; um número isolado não indica se o resultado é bom.
Métrica semi-aditivaCuidado com o tempo

Métrica que pode ser agregada em algumas dimensões, mas não somada diretamente em todas — principalmente ao longo do tempo.

No projeto
Ocupação precisa considerar as noites dentro do período; somar percentuais mensais produz resultado incorreto.
Solução
Recalcule numerador e denominador no contexto total.
04

Indicadores de hotelaria

Diárias vendidasVolume

Total de noites ocupadas por reservas válidas. Uma reserva de três noites representa três diárias vendidas.

No projeto
Considere hospedagens realizadas e hospedadas; exclua canceladas, no-show e apenas confirmadas.
Uso
É o denominador do ADR e o numerador da ocupação.
Diárias disponíveisCapacidade

Total de noites que poderiam ser vendidas no período. Com 100 quartos durante 30 dias, há 3.000 diárias disponíveis.

Fórmula básica
Quartos disponíveis × Dias do período.
Uso
É o denominador da ocupação e do RevPAR.
ADRPreço médio

Average Daily Rate: valor médio recebido por diária vendida.

Fórmula
Receita de Hospedagem ÷ Diárias Vendidas.
Interpretação
ADR alto indica preço maior, mas não informa quantos quartos ficaram vazios.
Taxa de ocupaçãoUso da capacidade

Percentual das diárias disponíveis que foram vendidas no período.

Fórmula
Diárias Vendidas ÷ Diárias Disponíveis.
Cuidado
Uma estadia que atravessa meses deve contribuir com as noites correspondentes a cada período.
RevPARReceita por capacidade

Revenue per Available Room: receita de hospedagem gerada por quarto disponível.

Fórmula
Receita de Hospedagem ÷ Diárias Disponíveis, ou ADR × Ocupação.
Interpretação
Ajuda a comparar hotéis equilibrando preço e ocupação.
Revenue managementEstratégia

Prática de ajustar preço e disponibilidade conforme demanda, antecedência, canal, época e perfil do hotel.

No projeto
A tarifa varia por sazonalidade, dia da semana e lead time.
Pergunta
O hotel poderia cobrar mais em períodos de alta ocupação ou estimular demanda nos períodos fracos?
SazonalidadePadrão no tempo

Variação de demanda que tende a se repetir conforme mês, estação, férias, feriados ou dia da semana.

No projeto
Praia ganha força no verão; serra, no inverno; hotéis urbanos, em dias úteis.
Visual
Linha mensal ou heatmap por mês e perfil de destino.
Lead timeAntecedência

Número de dias entre a data em que a reserva foi criada e o check-in.

Fórmula
Data_Checkin − Data_Reserva.
Uso
Ajuda a planejar preço e campanha: última hora e reserva antecipada têm comportamentos diferentes.
No-showStatus de reserva

Situação em que o hóspede não comparece para o check-in e não utiliza a hospedagem.

No projeto
É um status diferente de cancelamento.
Análise
Compare taxa de no-show por canal, antecedência e hotel para orientar políticas de garantia.
Check-inEntrada

Procedimento que registra a chegada do hóspede e o início da estadia.

No projeto
Data_Checkin é usada para calcular noites, lead time e análise de chegada.
Validação
Deve ocorrer depois da reserva e antes do check-out.
Check-outSaída

Procedimento que encerra a hospedagem e registra a saída do hóspede.

No projeto
Data_Checkout − Data_Checkin determina o número de noites.
Validação
A data deve ser posterior ao check-in.
Taxa de cancelamentoPerda de reservas

Percentual das reservas que foram canceladas dentro do conjunto analisado.

Fórmula
Reservas canceladas ÷ Total de reservas.
Análise
Compare canal, hotel, antecedência e período antes de propor uma política.
Comissão de canalCusto de venda

Percentual da reserva pago ao intermediário que realizou a venda.

No projeto
BookNow cobra 18%, ViajaMais 15% e Agência 10%; canais diretos têm 0% nesta simulação.
Impacto
Receita bruta semelhante pode gerar receita líquida diferente.
Receita brutaAntes dos descontos

Valor total cobrado pelas hospedagens antes de descontar comissão de canal ou outros custos.

No projeto
Noites × Diária média cobrada para reservas válidas.
Limite
Não representa necessariamente o valor que permanece com o hotel.
Receita líquida de canalApós comissão

Receita após descontar a comissão paga ao canal que originou a reserva.

Fórmula
Receita bruta × (1 − percentual de comissão).
Uso
Permite comparar canais diretos, OTAs e agências com justiça.
SLAPrazo de atendimento

Service Level Agreement: compromisso de tempo para resolver um chamado, de acordo com a prioridade.

No projeto
Alta = 2 horas, Média = 8 horas e Baixa = 24 horas.
KPI
Chamados dentro do prazo ÷ Total de chamados.
05

Análise e entrega

AnalyticsUso dos dados

Conjunto de práticas para transformar dados em explicações, previsões ou decisões. Vai além de construir gráficos.

No projeto
Você deve identificar padrões e propor três ações sustentadas pelos indicadores.
Estrutura
Contexto → evidência → recomendação.
Segmentação de dadosFiltro visual

Visual do Power BI que permite ao usuário escolher valores para filtrar os demais elementos da página.

No projeto
Use período, hotel, bandeira, canal e perfil de destino.
Usabilidade
Mostre claramente quando há filtro aplicado e ofereça forma fácil de limpar a seleção.
BenchmarkReferência de comparação

Valor usado para interpretar desempenho: meta, média da rede, melhor hotel ou período anterior.

No projeto
Compare o RevPAR de cada hotel com a média da rede e com seu próprio histórico.
Por que importa
Sem comparação, um número isolado não informa se o resultado é bom ou ruim.
InsightDescoberta acionável

Conclusão relevante obtida dos dados que explica um comportamento ou revela uma oportunidade.

No projeto
Entregue pelo menos três insights sustentados por medidas e visuais.
Boa formulação
Diga o que aconteceu, onde, quanto mudou e por que isso merece ação.
